What we used

A commercially clean stack, each piece earning its place.

vision model

FashionCLIP MIT

CLIP further trained on 800K fashion pairs. Zero-shot: it compares each image to text labels, no classifier head to train. On this task, domain beat model size.

knowledge graph

Neo4j Community

Garments, materials, categories, seasons and regions as nodes. The reasoning about weather lives here as edges, not in the model.

segmentation

u2net_cloth_seg

rembg's cloth model keeps the garment and drops the wearer, and splits a photo into upper, lower and full-body pieces.

backend

FastAPI + PyTorch

The whole pipeline behind a small HTTP contract. The model loads on first use so the server starts instantly.

frontend

React + TypeScript

A Vite wardrobe app. Nothing is decided in the browser: every label and number came back from the API.

evaluation only

Fashionpedia

46 classes, 294 attributes. Used to measure accuracy against labelled ground truth, and to fine-tune, never shipped.

How it works

Photo in, garment out. Weather is derived, not predicted.

isolate the clothing→ read attributes→ warmth score→ match seasons

The model can only see pixels: wool, a coat, long sleeves.

What temperature that suits is knowledge, not appearance. So every material and category carries a warmth weight, seeded into the graph. They are added, matched to season windows, and the answer comes back as a Cypher traversal.

Change a number in the graph and every stored garment re-answers, no retraining. And when a person corrects a label, the graph updates on the spot while the fix is also saved to retrain the model later.

Built around the model

A wardrobe, not a demo box.

Multi-garment

One photo of an outfit becomes separate upper, lower and full-body garments.

Cloth-only cutout

The garment is kept and the wearer removed, so the wardrobe is faceless.

Mannequin wardrobe

Garments hang by body region; click a part of the figure to browse it.

Fit recommender

An outfit for the weather, from what you own, tilted by your stated taste.

Price & wash care

A brand estimates a price; the fibre suggests a wash. Both editable.

Correction loop

Flag a wrong reading: the graph fixes now, the model retrains later.

Plus gap analysis of what the wardrobe can't dress for, most / least valuable outfit, and an admin statistics page, separate from the owner's view and never confused with accuracy.

Room for improvement

Where it goes next.

01

A conversational layer

Ask the wardrobe in plain language, like "what can I wear below zero?" An LLM turns the question into Cypher through parameterised query templates, never free-form generated queries, because the graph has a single admin account. The seams are already in place.

02

More fine-tuning, beyond category

Material, colour and sleeve are still zero-shot because Fashionpedia has no fibre labels. A fabric-annotated dataset would let the warmth score rest on a validated material, not a guess. More data plateaued near 80%, so the next gain is in the hard confusions (blazer vs jacket, sweater vs coat) that differ by cut, not resolution.

03

More garment pieces in the model

Twelve categories today. Fashionpedia labels forty-six: footwear, bags and accessories, plus jumpsuits, capes and vests currently left out. Widening the ontology, and the warmth and region tables with it, turns single garments into whole outfits the graph can reason over.

04

Close the honest loops

One final run on the held-out test half, retraining on the corrections people submit and reporting the dev number before and after, and a real product feed so prices are quoted rather than estimated.
